Operating Model and Safety

7 items
  • Start your notes file with sprint goal, scope, and non-goals.
  • Write success criteria before prompting.
  • Record your recovery plan (for example: git restore, branch reset strategy, session restart).
  • Do a quick environment check (git status, tests/build command available).

Self-check:

  • I can state the exact task in one sentence.
  • I have at least one explicit non-goal.
  • I know how I will verify success.

10-20 min

Quick Build Baseline (You Drive)

5 items
  • Run a small prompt to inspect the task area and propose a plan.
  • Ask for clarifying questions if the plan is ambiguous.
  • Approve execution only after the plan includes verification steps. [Source: https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview] [Source: https://docs.anthropic.com/en/docs/test-and-evaluate/define-success]
  • Save the prompt and plan in your notes.

Practice loop cue:

  • If the plan is vague, do not proceed. Narrow scope and restate success criteria.

20-35 min

Lab Sprint 1 (Guided): Plan-First Bugfix

7 items
  • Run the first execution pass on a small bugfix or failing test.
  • Keep edits scoped to the minimum relevant files.
  • Review the diff before rerunning tests. [Source: https://git-scm.com/docs/git-diff]
  • Run verification and capture the result.

Checkpoint:

  • Acceptance criteria existed before edits
  • Diff was reviewed before verification
  • Verification evidence captured

35-45 min

Session Control and Context Hygiene

5 items
  • Inspect the current session state: is the context still focused?
  • If the agent drifted, rewrite the task with progressive disclosure (task, file scope, criteria only). [Source: https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/long-context-tips]
  • Decide whether to continue, compact, clear, or restart based on signal-to-noise.
  • Record what triggered your decision.

Reflection prompt:

  • What information in the last prompt/session was unnecessary?

45-60 min

Lab Sprint 2: Refactor with Guardrails

7 items
  • Pick one small cleanup/refactor in the same area or adjacent code.
  • Ask for 2 approaches and choose the lower-risk option.
  • Require incremental steps plus risk notes after each step. [Source: https://martinfowler.com/articles/workflowsOfRefactoring.html]
  • Review diffs and rerun checks after each step if possible.

Checkpoint:

  • Two approaches compared
  • Verification checklist present
  • Refactor stayed behavior-preserving

60-70 min

MCP / Tooling Extension Preview (Optional Solo Demo)

3 items
  • If you have a safe read-only MCP server available, run one small inspection task.
  • Write the trust boundary: what the tool can read, what it can change, and what you will verify manually. [Source: https://docs.anthropic.com/en/docs/claude-code/mcp] [Source: https://modelcontextprotocol.io/specification/2025-06-18]
  • If you do not have MCP set up, use this block to review REFERENCE_PACK.md and note one future experiment.

  • Note the transferable parts (task framing, constraints, verification) versus tool-specific parts (commands, flags, approvals). [Source: https://github.com/openai/codex] [Source: https://platform.openai.com/docs/guides/codex] [Source: https://developers.openai.com/codex/prompting-guide]

80-90 min

Debrief, Self-Assessment, and Next Steps

4 items
  • Score yourself using the workshop rubric in RUBRICS.md.
  • Write one workflow change you will keep.
  • Pick the next lab based on your weakest dimension.
  • If the task is complete, commit with a clear message.

90-Minute Personal Sprint Plan (Self-Paced)

Use this file as a solo practice sprint. You will work through a structured 90-minute session that combines planning, execution, verification, and reflection. Keep it timeboxed and evidence-driven.

TOC Mapping (Required)

  • TOC 1: Claude Code operations, permissions, session controls, Git workflow basics
  • TOC 2: Clarifying questions, plan-first prompting, acceptance criteria, verification design
  • TOC 3: Incremental refactor mindset and diff review habits
  • TOC 4: Context hygiene and progressive disclosure
  • TOC 5: Bonus transfer compare (optional final segment)

Workshop Outcomes

By the end of this sprint, you will:

  • Frame a coding task with explicit success criteria before editing
  • Run at least one plan-first bugfix or refactor loop
  • Review diffs and capture verification evidence
  • Practice context narrowing or session reset decisions
  • Leave with a concrete next-step plan for labs or capstone

Materials Needed

  • A local practice repo (preferably with tests or a reproducible bug)
  • Working Git (git status, git diff, git switch) [Source: https://git-scm.com/docs] [Source: https://git-scm.com/docs/git-diff] [Source: https://git-scm.com/docs/git-switch]
  • Claude Code (or equivalent coding agent environment)
  • PROMPT_CARDS.md, RUBRICS.md, and LABS.md open in a side window
  • A simple notes file for evidence capture (prompt, plan, diff summary, test results, reflection)

Pre-Workshop Setup (15-30 min before you start)

Reframe for self-paced use: do this before your timer starts.

  • Confirm the repo builds/tests at baseline.
  • Create a new branch for the sprint.
  • Pick one task: bugfix, small refactor, or feature tweak.
  • Decide your verification method (tests, lint, manual repro).
  • Set your safety rules: no destructive Git commands, diff review before commit, one task only. [Source: https://docs.anthropic.com/en/docs/claude-code/security] [Source: https://git-scm.com/book/en/v2]

Sprint Prompt Starters (Ready to Use)

Demo Prompt 1 (Quick Build)

Before making changes, inspect the relevant files and propose a short plan. Ask clarifying questions if needed. Define acceptance criteria and how you will verify success. Wait for approval before editing.

Demo Prompt 2 (Refactor)

Propose 2 refactor approaches for this code. Prioritize minimal behavioral risk. For the chosen approach, break work into small steps and include verification after each step. Summarize diffs and regression risks as you go.

Workshop Troubleshooting (Fast Responses)

  • If the agent edits unrelated files: restate file scope and non-goals; ask for a revised plan first. [Source: https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/long-context-tips]
  • If the plan skips verification: require test/manual checks explicitly before approval. [Source: https://docs.anthropic.com/en/docs/test-and-evaluate/develop-tests]
  • If the session gets noisy: summarize the task in a fresh prompt with only current requirements.
  • If verification fails late: checkpoint the current branch state, narrow the bug, and retry a smaller step.

Assessment Evidence (End of Workshop)

Save these artifacts before ending the sprint:

  • Final prompt(s) used
  • Plan (including acceptance criteria and verification method)
  • Diff summary (what changed and why)
  • Verification evidence (tests, lint, manual repro)
  • Self-assessment score + one reflection note

Reflection Prompts

  • Which part of the sprint produced the most value: planning, execution, review, or recovery?
  • What caused drift or wasted time?
  • What will you change in your next 90-minute sprint?
