23:T1ac8,# 90-Minute Workshop Plan (Interactive)

This is a high-density, hands-on entry workshop that introduces safe agentic coding workflows with Claude Code and a short Codex CLI transfer comparison.

## TOC Mapping (Required)

- TOC 1: Setup, session commands, permissions, quick build, Git, MCP preview
- TOC 2: Clarifying questions, plan mode, context hygiene, reliable package choices
- TOC 4: Signal-to-noise + progressive disclosure (light intro)
- TOC 5: Bonus Codex CLI transfer (short compare)

## Workshop Outcomes

By minute 90, learners should be able to:

- Run one plan-first coding task end-to-end with verification and commit. [Source: https://docs.anthropic.com/en/docs/test-and-evaluate/define-success] [Source: https://git-scm.com/docs/git-commit]
- Explain why permissions/sandboxing matter in agentic workflows. [Source: https://docs.anthropic.com/en/docs/claude-code/security]
- Use a context-minimizing prompt and identify one context bloat anti-pattern. [Source: https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/long-context-tips]
- Compare Claude Code and Codex CLI at a workflow level (not feature memorization). [Source: https://github.com/openai/codex] [Source: https://platform.openai.com/docs/guides/codex]

## Materials Needed

- Training repo with tests and 1-2 intentional bugs
- Projector/demo terminal
- Printed/shared `PROMPT_CARDS.md`
- `LABS.md` Lab 1 + Lab 2 excerpts
- Git installed for all learners [Source: https://git-scm.com/docs]

## Pre-Workshop Setup (15-30 min before learners arrive)

- Reset training repo to workshop start branch.
- Confirm CLI login and network access.
- Open docs tabs for citations and quick reference.
- Prepare one fallback local transcript if demo fails.

## Agenda (Minute-by-Minute)

### 0-10 min — Operating Model and Safety

- Explain the workflow: prompt -> plan -> verify -> commit.
- Cover permissions/sandboxing and why blind approvals are risky. [Source: https://docs.anthropic.com/en/docs/claude-code/security]
- Show class norms: small diffs, tests first, ask clarifying questions.

Activity:
- Learners write 2 risks of “just let the agent run everything”.

### 10-20 min — Quick Build Demo (Instructor)

- Instructor performs a small bugfix or feature tweak.
- Start with a plan-first prompt and explicit success criteria. [Source: https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview] [Source: https://docs.anthropic.com/en/docs/test-and-evaluate/define-success]
- Review diff before running tests. [Source: https://git-scm.com/docs/git-diff]

Teaching points:
- Clarifying question quality
- Naming constraints and non-goals
- Verifying before commit

### 20-35 min — Lab Sprint 1 (Guided): Plan-First Bugfix

Use `LABS.md` Lab 1.

Learner tasks:
- Draft prompt with acceptance criteria
- Run agent
- Inspect diff and tests
- Commit small patch

Checkpoint (minute 30):
- Facilitator pauses room and asks learners to share acceptance criteria and one diff risk they checked.

### 35-45 min — Session Control + Context Hygiene

- Demo session/status commands and context reset/compaction decisions (version-sensitive commands should be verified with the installed CLI). [Source: https://docs.anthropic.com/en/docs/claude-code/slash-commands]
- Teach signal-to-noise and progressive disclosure (only add context when needed). [Source: https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/long-context-tips]

Micro-activity:
- Learners rewrite an overstuffed prompt into a focused one.

### 45-60 min — Lab Sprint 2: Refactor with Guardrails

Use `LABS.md` Lab 2.

Learner tasks:
- Ask for refactor plan only
- Add test/verification checklist before execution
- Implement in small steps
- Use Git checkpoints (commit or stash/branch as instructed)

Source-backed emphasis:
- Incremental refactoring reduces risk and keeps feedback tight. [Source: https://martinfowler.com/articles/workflowsOfRefactoring.html]

### 60-70 min — MCP / Tooling Extension Preview (Instructor Demo)

- Show one safe, read-only MCP use case (e.g., docs/search/context retrieval).
- Explain MCP trust boundaries, tool selection, and least-privilege mindset. [Source: https://docs.anthropic.com/en/docs/claude-code/mcp] [Source: https://modelcontextprotocol.io/specification/2025-06-18]
- Mention subagents/hooks as advanced extensions (covered in full course). [Source: https://docs.anthropic.com/en/docs/claude-code/sub-agents] [Source: https://docs.anthropic.com/en/docs/claude-code/hooks]

### 70-80 min — Bonus Compare: Codex CLI Workflow Transfer

- Run a tiny equivalent task or show prepared transcript.
- Compare prompt structure, approvals/tools model, and verification workflow.
- Emphasize transferable habits over command memorization. [Source: https://github.com/openai/codex] [Source: https://platform.openai.com/docs/guides/tools-shell] [Source: https://developers.openai.com/codex/prompting-guide]

### 80-90 min — Debrief + Assessment + Next Steps

- Quick rubric self-score (use `RUBRICS.md` workshop rubric)
- Group debrief: what improved output quality most?
- Assign follow-up labs by track (`LEARNING_PATHS.md`)

## Instructor Script Prompts (Ready to Use)

### Demo Prompt 1 (Quick Build)

"Before writing code, propose a 5-step plan. List assumptions, risks, and exactly how you will verify success (tests, commands, files to inspect). Then wait for approval."

Why this works: asks for plan, assumptions, and verification, which aligns with prompt/evaluation best practices. [Source: https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview] [Source: https://docs.anthropic.com/en/docs/test-and-evaluate/define-success]

### Demo Prompt 2 (Refactor)

"Refactor incrementally. Keep behavior unchanged. After each step, summarize the diff and what regression risk it might introduce. Stop if tests fail."

Why this works: encourages iterative refactoring and verification loops. [Source: https://martinfowler.com/articles/workflowsOfRefactoring.html] [Source: https://docs.anthropic.com/en/docs/test-and-evaluate/develop-tests]

## Workshop Troubleshooting (Fast Responses)

- If installs fail: switch to preconfigured VM/container or follow along on shared screen.
- If agent output is noisy: force a plan-only step and narrow file scope. [Source: https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/long-context-tips]
- If learners are blocked by Git: use a helper branch and resume lab at next checkpoint. [Source: https://git-scm.com/docs/git-switch]

## Assessment Evidence (End of Workshop)

Collect from each learner/team:

- Prompt used
- Acceptance criteria list
- Diff screenshot or patch summary
- Test/check output
- Commit hash/message (optional in beginner path)
- 2-sentence reflection on what improved/worsened output quality
