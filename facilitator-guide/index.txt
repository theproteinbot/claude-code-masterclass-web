19:T2612,# Facilitator Guide

This is the instructor runbook for delivering the masterclass live. It assumes the facilitator has reviewed `MASTERCLASS_OVERVIEW.md`, `WORKSHOP_90MIN.md`, and `LABS.md`.

## TOC Coverage Map (Required)

- TOC 1 (Claude Code): primary live demos, setup, session controls, permissions, MCP/subagents/hooks
- TOC 2 (Fundamentals): prompt framing, planning, clarifying questions, context hygiene
- TOC 3 (Advanced): refactor/review orchestration and convergence exercises
- TOC 4 (Context Engineering): context layering and long-context mitigation techniques
- TOC 5 (Codex bonus): transfer module / comparison lab

## Facilitation Objectives

- Teach safe operation, not just feature discovery. [Source: https://docs.anthropic.com/en/docs/claude-code/security]
- Model plan-first behavior and explicit success criteria before coding. [Source: https://docs.anthropic.com/en/docs/test-and-evaluate/define-success]
- Normalize verification, rollback, and iterative refinement instead of one-shot prompting. [Source: https://docs.anthropic.com/en/docs/test-and-evaluate/develop-tests] [Source: https://git-scm.com/docs/git-reflog]
- Keep learners active; convert every major concept into a short practice loop.

## Pre-Flight Checklist (Day Before)

- Verify all demo commands in a clean shell session.
- Clone/reset the training repo to known state (`main`, tags, or prepared branches).
- Validate tests, fixtures, and intentional bugs still reproduce.
- Check internet access to Anthropic/OpenAI/Git docs for live citations.
- Prepare local copies/screenshots of docs in case of network instability.
- Confirm API credentials and org policies for tool use are available.
- Rehearse permission prompts and refusal/approval examples. [Source: https://docs.anthropic.com/en/docs/claude-code/security]
- Rehearse an MCP demo using a read-only server first. [Source: https://docs.anthropic.com/en/docs/claude-code/mcp]

## Room / Delivery Setup Checklist (Day Of)

- Primary machine connected to projector with readable terminal font size
- Backup machine or recorded terminal capture
- Shared repo URL and starter branch visible
- Timer visible (strictly enforce activity windows)
- Co-facilitator or helper for troubleshooting (recommended for >15 learners)
- Printed or shared `PROMPT_CARDS.md`

## Recommended Teaching Flow (Live)

1. Safety and operating model (permissions, sandboxing, verification) [Source: https://docs.anthropic.com/en/docs/claude-code/security]
2. First constrained task with plan-first prompt and acceptance criteria [Source: https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview] [Source: https://docs.anthropic.com/en/docs/test-and-evaluate/define-success]
3. Diff/test review and commit discipline [Source: https://git-scm.com/docs/git-diff] [Source: https://git-scm.com/docs/git-commit]
4. Context management and session controls [Source: https://docs.anthropic.com/en/docs/claude-code/slash-commands] [Source: https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/long-context-tips]
5. Advanced extensibility (MCP/subagents/hooks) with explicit risk boundaries [Source: https://docs.anthropic.com/en/docs/claude-code/mcp] [Source: https://docs.anthropic.com/en/docs/claude-code/sub-agents] [Source: https://docs.anthropic.com/en/docs/claude-code/hooks]
6. Bonus transfer to Codex CLI (time permitting) [Source: https://github.com/openai/codex] [Source: https://platform.openai.com/docs/guides/codex]

## Instructor Demo Patterns (Use Repeatedly)

### Pattern 1: Plan → Execute → Verify → Commit

- Ask for a plan with explicit assumptions and unknowns.
- Add success criteria and non-goals before execution. [Source: https://docs.anthropic.com/en/docs/test-and-evaluate/define-success]
- Run or inspect tests/checks; compare diffs; discuss tradeoffs. [Source: https://docs.anthropic.com/en/docs/test-and-evaluate/develop-tests] [Source: https://git-scm.com/docs/git-diff]
- Make a small commit with a meaningful message. [Source: https://git-scm.com/docs/git-commit]

### Pattern 2: Narrow Context → Expand Only If Needed

- Start with task + relevant files only.
- Add logs, docs, or surrounding modules only when the model shows uncertainty or mismatch.
- Use compaction/summary before context becomes noisy. [Source: https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/long-context-tips] [Source: https://docs.anthropic.com/en/docs/claude-code/slash-commands]

### Pattern 3: Tooling Escalation Ladder

- Baseline local reasoning
- Add repo search / docs references
- Add MCP (read-only)
- Add subagents for decomposition
- Add hooks/automation once workflow is stable

This order limits failure modes while learners build confidence. [Source: https://docs.anthropic.com/en/docs/claude-code/mcp] [Source: https://docs.anthropic.com/en/docs/claude-code/sub-agents] [Source: https://docs.anthropic.com/en/docs/claude-code/hooks]

## Common Failure Modes and How to Teach Through Them

### 1. Learner jumps straight to coding without acceptance criteria

- Intervention: pause and require 3 acceptance bullets + 2 non-goals.
- Why: clearer definitions improve reliability and reduce churn. [Source: https://docs.anthropic.com/en/docs/test-and-evaluate/define-success]

### 2. Context bloat causes wrong-file edits or incoherent changes

- Intervention: reset/narrow context, restate objective, provide only relevant files.
- Teach: progressive disclosure and signal-to-noise management. [Source: https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/long-context-tips]

### 3. Over-trusting autonomous shell/tool actions

- Intervention: stop, inspect commands, discuss permissions/sandboxing, require dry-run or read-only first.
- Teach: permission posture is part of engineering, not an annoyance. [Source: https://docs.anthropic.com/en/docs/claude-code/security]

### 4. Learner cannot recover from bad changes

- Intervention: run `git status`, `git diff`, `git restore`, branch rollback, and `git reflog` demo.
- Teach: reversibility is the enabler of safe experimentation. [Source: https://git-scm.com/docs/git-status] [Source: https://git-scm.com/docs/git-restore] [Source: https://git-scm.com/docs/git-reflog]

### 5. Prompt injection / unsafe instructions from external text or tools

- Intervention: isolate external content, restate trusted instructions, require explicit confirmation before action.
- Teach: injection mitigation and guardrail design. [Source: https://docs.anthropic.com/en/docs/test-and-evaluate/strengthen-guardrails/mitigate-jailbreaks]

## Troubleshooting Guide (Operational)

### Install / CLI Issues

- Symptom: CLI not found
  - Check PATH, shell reload, reinstall steps from official quickstart. [Source: https://docs.anthropic.com/en/docs/claude-code/quickstart] [Source: https://help.openai.com/en/articles/11096431-openai-codex-cli-getting-started]
- Symptom: auth failure
  - Re-authenticate; verify org/project/API settings and environment vars.
- Symptom: shell tool denied
  - Inspect approvals/permissions settings and org policy defaults. [Source: https://docs.anthropic.com/en/docs/claude-code/settings] [Source: https://docs.anthropic.com/en/docs/claude-code/security]

### Git Issues

- Symptom: merge conflict during lab
  - Pause class; switch to prepared branch or use conflict-resolution mini-demo.
- Symptom: lost changes
  - Use `git reflog` to locate prior HEAD. [Source: https://git-scm.com/docs/git-reflog]

### MCP Issues

- Symptom: server connects but tools fail
  - Verify transport/config, permissions, and tool names; start with a simpler read-only server. [Source: https://docs.anthropic.com/en/docs/claude-code/mcp] [Source: https://modelcontextprotocol.io/docs/getting-started/intro]

### Model / Quality Issues

- Symptom: incoherent implementation
  - Reframe with plan-first prompt, success criteria, explicit file list, and test plan.
- Symptom: repeated low-value loops
  - Ask for alternatives, compare proposals, reduce task scope, or switch to a review/refactor prompt shape. [Source: https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview]

## Facilitation Tactics for Hands-On Labs

- Timebox aggressively (5-12 minutes per task).
- Use checkpoint pauses: “Hands off keyboard, compare diff.”
- Ask learners to narrate verification steps before showing results.
- Rotate one learner to be “safety reviewer” (permissions + Git rollback readiness).
- Have advanced learners coach on process, not code output.

## Answer Key Policy (How to Use)

- `LABS.md` includes expected outcomes and sample prompt patterns, not a single canonical implementation.
- Grade process quality first (planning, verification, rollback, evidence), then code quality.
- Only reveal full solution branches after learners attempt the lab.

## Assessment Operations

- Use `RUBRICS.md` live for checkpoint scoring (fast 0/1/2 scoring).
- Capture evidence artifacts: prompt, plan, diff, test output, commit(s), reflection note.
- For capstone, require a short demo plus written verification checklist.

## Facilitation Debrief Questions

- What failure did you detect before it reached commit?
- Which prompt constraint improved output quality most?
- Where did context size hurt quality?
- Which Git recovery command saved time?
- Which workflow step should become a team standard?

## Post-Class Follow-Through (Instructor)

- Share annotated solution branches and rubric results.
- Collect confusing prompts or failure cases and convert them into new prompt cards.
- Update internal guidance when tooling/docs change. [Source: https://docs.anthropic.com/en/docs/claude-code/overview] [Source: https://github.com/openai/codex]
